## What changed

Previous DEPLOYLOG shipped `nostr.mjs note`. This is triage item #2 of 3: the agent can now publicly amplify someone else's kind:1 text note (without commentary). With this, the public toolkit covers all four basic social shapes plus the "amplify" mechanic:

```
nostr.mjs repost <note-id-or-bech32>
```

Per NIP-18, kind:6 content is `JSON.stringify(cleanTarget)` -- the verbatim JSON of the resolved event. The agent's nsec signs this re-emission of the original author's content. This is what every modern Nostr client emits (Damus / Amethyst / Primal / Nostrudel / coracle); empty content is allowed only for NIP-70-protected events, which we don't consume.

Defenses at the CLI:
- **Target decoder is strict** (same as like): `decodeEventReference` accepts raw hex / `note1` / `nevent1` only. Rejects `npub1` / `nsec1` / `naddr1` / bad-checksum bech32 BEFORE any network call.
- **p-tag derived from the RESOLVED, signature-verified event** (same security-critical invariant as like): the kind:6's `p` tag uses `resolved.target.pubkey`, NEVER any `nevent1.author` hint. Test 178 enforces this against a deliberately-mismatched author hint.
- **7-field whitelist for content**: `cleanTarget = {id, pubkey, created_at, kind, tags, content, sig}` is built explicitly. `verifyEvent` only canonicalizes the 7 NIP-01 fields when checking sig, so a relay could decorate the event with extra top-level fields (e.g. `relay_metadata`) that pass verify unnoticed. Naive `JSON.stringify(target)` would emit those extras under our nsec; the whitelist prevents that. Test 186 verifies the defense against an explicitly-decorated mock payload.
- **Self-repost refused at the post-resolve gate**: `target.pubkey === myHex` -> `cannot-repost-own-note`. The gate fires AFTER both nsec decode and resolveEvent (target.pubkey comes from the verified resolved event), so a lying `nevent1.author` hint cannot bypass it.
- **Strict argv**: missing positional / trailing positional / unknown flag all reject pre-network. Tests 175-177 verify zero REQ frames sent for these.
- **No body / no comment input**: this is pure reshare per NIP-18. Quote-repost (kind:1 with `q` tag) is a separate deferred feature.

19 new test blocks (groups 168-186), 50 new assertions, **441/441 PASS** (up from 391).

Out of scope (deferred):
- Quote-repost (kind:1 with `q` tag pointing at another event)
- Generic-repost (kind:16 for non-kind:1 targets, per NIP-18 sibling kind)
- NIP-70-protected repost variant (would need empty content + explicit `--protected` flag; defer until we actually consume NIP-70 events)
- Un-repost via kind:5

## Setup steps

All commands run as root on the fagents host.

```bash
INFRA_USER="fagents"
INFRA_HOME=$(eval echo "~$INFRA_USER")
CLI_DIR="$INFRA_HOME/workspace/fagents-cli"
```

### 1. Preflight chown + pull fagents-cli

Per the DEPLOYLOG README template (`3c03acf`):

```bash
sudo chown -R "$INFRA_USER:fagent" "$INFRA_HOME/repos"
sudo chown -R "$INFRA_USER:fagent" "$INFRA_HOME/workspace"
sudo -Hu "$INFRA_USER" git -C "$CLI_DIR" pull origin main
```

No `npm install` (no new deps).

### 2. Re-render the nostr skill for each agent

```bash
for COMMS_USER in ftf ftl ftw; do
    AGENT_DIR="$INFRA_HOME/.agents/$COMMS_USER"
    [ -d "$AGENT_DIR/skills/nostr" ] || continue
    sudo sed "s|__CLI_DIR__|$CLI_DIR|g" "$CLI_DIR/nostr/SKILL.md" \
        | sudo tee "$AGENT_DIR/skills/nostr/SKILL.md" >/dev/null
    sudo chown "$INFRA_USER:fagent" "$AGENT_DIR/skills/nostr/SKILL.md"
    sudo chmod 644 "$AGENT_DIR/skills/nostr/SKILL.md"
done
```

Existing sudoers rule (`sudo -u fagents $CLI_DIR/nostr.mjs *`) covers the new `repost` subcommand.

### 3. No daemon restart

`nostr.mjs serve` is unchanged. `repost` is a one-shot CLI invocation.

## Doctor

```bash
INFRA_HOME=$(eval echo "~fagents")
CLI_DIR="$INFRA_HOME/workspace/fagents-cli"

# 1. repost subcommand visible in help output
sudo -Hu fagents "$CLI_DIR/nostr.mjs" help | python3 -c "
import json, sys
cmds = json.load(sys.stdin)['commands']
checks = [c for c in cmds if c.startswith('repost ')]
print(f'ok: repost subcommand in help' if len(checks) == 1 else f'FAIL: expected 1 repost entry, got {len(checks)}')
"

# 2. Each agent's installed SKILL.md has the new section + the amplification warning
for u in ftf ftl ftw; do
    AD="$INFRA_HOME/.agents/$u"
    [ -f "$AD/skills/nostr/SKILL.md" ] || continue
    has_section=$(grep -c '^## Reposting a note' "$AD/skills/nostr/SKILL.md")
    has_warning=$(grep -c 'amplifies the original note' "$AD/skills/nostr/SKILL.md")
    if [ "$has_section" = "1" ] && [ "$has_warning" = "1" ]; then
        echo "ok: $u SKILL.md has repost section + amplification warning"
    else
        echo "FAIL: $u SKILL.md missing repost section -- re-run step 2"
    fi
done

# 3. Negative-path smokes (no network, no publish):
#    no positional -> missing-target-event-id
sudo -Hu fagents "$CLI_DIR/nostr.mjs" repost 2>/dev/null | python3 -c "
import json, sys
try:
    d = json.loads(sys.stdin.read().strip())
    print('ok: missing positional rejected' if d.get('error') == 'missing-target-event-id' else f'FAIL: unexpected: {d}')
except Exception as e:
    print(f'FAIL: malformed: {e}')
"

#    npub1 input -> bad-target-event-id (exercises decoder rejection)
SELF_NPUB=$(sudo -Hu fagents "$CLI_DIR/nostr.mjs" whoami | python3 -c "import json,sys; print(json.load(sys.stdin)['npub'])")
sudo -Hu fagents "$CLI_DIR/nostr.mjs" repost "$SELF_NPUB" 2>/dev/null | python3 -c "
import json, sys
try:
    d = json.loads(sys.stdin.read().strip())
    print('ok: npub1 rejected as bad-target-event-id' if d.get('error') == 'bad-target-event-id' else f'FAIL: unexpected: {d}')
except Exception as e:
    print(f'FAIL: malformed: {e}')
"
```

Don't include a live `repost <real-note-id>` smoke -- that would publish a real reshare of a real note on public relays. Manual dev-side smoke (against a throwaway nsec) is documented in the impl notes.

No daemon restart for revert. Any kind:6 events already published cannot be cleanly retracted (kind:5 deletions are unreliable). The skill text warns the agent about this -- a repost is effectively permanent and carries the original note's body verbatim.

## Notes

- **Repost sits between like and follow in social-signal strength.** Operators should monitor the agent's npub reaction stream + reposts post-deploy and intervene at the prompt/skill level if it amplifies adversarial bait.
- **No NOSTR_REPOST_ALLOWED_TARGETS by design** -- the skill carries the trust posture, same as reply / like / note / profile / follow.
- **Manual dev-side smoke** performed against damus.io / nos.lol / relay.primal.net with a throwaway nsec: searched for a kind:1 by another author, reposted it via raw hex + via note1 (both succeeded with valid kind:6 events emitted), attempted self-repost (rejected as `cannot-repost-own-note`).
