## What changed

Previous DEPLOYLOG shipped `nostr.mjs like`. This is the natural follow-up: the agent can now originate a public timeline post, not just react to existing ones. With this, the agent's public toolkit covers the four basic shapes of social-media output -- `note` (originate), `reply` (respond), `like` (endorse one note), `follow` (endorse an author).

```
nostr.mjs note [--tag <topic>]... [--] <body>
```

Signs a kind:1 event with the agent's nsec and publishes to `NOSTR_RELAYS`. No parent reference, no NIP-10 chain.

Flag parsing is **prefix-only**:
- `--tag <topic>` is consumed at the head of argv.
- First non-flag token (or explicit `--` separator) starts the body region.
- Inside the body region, `--foo` is body text. This lets the agent post a body containing flag-shaped strings like "--draft is unsafe": `nostr.mjs note --tag warning -- --draft is unsafe`.

Defenses at the CLI:
- **Body**: passed through `sanitizeText` (strips invisible Unicode), rejected if empty-after-sanitize OR if sanitized bytes exceed 8 KB.
- **Tag values**: canonicalized via new `normalizeTopic` helper -- strip leading `#`, lowercase, sanitize-canonical (input MUST equal `sanitizeText(input)`; no silent strip of smuggling chars), whitespace-rejected, length-capped at 64 chars.
- **Tag dedup + cap**: `Set` deduplicates duplicate topics; distinct-tag count capped at 10. Duplicates of an existing topic are no-ops, NOT errors (so `--tag bitcoin --tag bitcoin` succeeds with one tag; 10 distinct + 1 duplicate also succeeds; 11 distinct fails with `too-many-tags`).
- **Strict argv (flag region)**: unknown flags before the body boundary reject as `unknown-flag-<name>`. After the boundary, flag-shaped tokens pass through as body text.
- **Body trust posture is two-mode and lives in the SKILL** (not in code): operator-dictated bodies are trusted; agent-drafted bodies derived from `<untrusted>` upstream (DMs, search results, profile metadata) require a pause trigger naming the source.

Tests: 22 new test blocks (groups 146-167) covering happy path, single + multi tags, leading `#` strip, dedup, the three distinct-tag cap semantics, all `bad-topic-*` failure modes, smuggled-Unicode topic rejection, missing body, empty-after-sanitize, body > 8 KB, unknown-flag-in-flag-region, publish-failed, smuggled body content stripped via sanitize, signed-by-own-pubkey, zero-REQ-for-pre-network-rejections, and four flag/body boundary scenarios (post-body flag is body, explicit `--` separator with and without prior tags, ordering). Note: null-byte-in-body has no CLI-level test (Node's `child_process.spawn` refuses null bytes in argv with `ERR_INVALID_ARG_VALUE`) -- the defensive check stays in code for library-level invocation paths.

**391/391 PASS** (up from 335; SIMPLIFY added 149c-d for embedded-# rejection + 153b for bad-tag-flag-shape, 388 -> 391).

## Setup steps

All commands run as root on the fagents host.

```bash
INFRA_USER="fagents"
INFRA_HOME=$(eval echo "~$INFRA_USER")
CLI_DIR="$INFRA_HOME/workspace/fagents-cli"
```

### 1. Preflight chown + pull fagents-cli

Per the DEPLOYLOG README template (`3c03acf`):

```bash
sudo chown -R "$INFRA_USER:fagent" "$INFRA_HOME/repos"
sudo chown -R "$INFRA_USER:fagent" "$INFRA_HOME/workspace"
sudo -Hu "$INFRA_USER" git -C "$CLI_DIR" pull origin main
```

No `npm install` (no new deps).

### 2. Re-render the nostr skill for each agent

```bash
for COMMS_USER in ftf ftl ftw; do
    AGENT_DIR="$INFRA_HOME/.agents/$COMMS_USER"
    [ -d "$AGENT_DIR/skills/nostr" ] || continue
    sudo sed "s|__CLI_DIR__|$CLI_DIR|g" "$CLI_DIR/nostr/SKILL.md" \
        | sudo tee "$AGENT_DIR/skills/nostr/SKILL.md" >/dev/null
    sudo chown "$INFRA_USER:fagent" "$AGENT_DIR/skills/nostr/SKILL.md"
    sudo chmod 644 "$AGENT_DIR/skills/nostr/SKILL.md"
done
```

Existing sudoers rule (`sudo -u fagents $CLI_DIR/nostr.mjs *`) covers the new `note` subcommand.

### 3. No daemon restart

`nostr.mjs serve` is unchanged. `note` is a one-shot CLI invocation.

## Doctor

```bash
INFRA_HOME=$(eval echo "~fagents")
CLI_DIR="$INFRA_HOME/workspace/fagents-cli"

# 1. note subcommand visible in help output
sudo -Hu fagents "$CLI_DIR/nostr.mjs" help | python3 -c "
import json, sys
cmds = json.load(sys.stdin)['commands']
checks = [c for c in cmds if c.startswith('note ')]
print(f'ok: note subcommand in help' if len(checks) == 1 else f'FAIL: expected 1 note entry, got {len(checks)}')
"

# 2. Each agent's installed SKILL.md has the new section + the originating-signal warning
for u in ftf ftl ftw; do
    AD="$INFRA_HOME/.agents/$u"
    [ -f "$AD/skills/nostr/SKILL.md" ] || continue
    has_section=$(grep -c '^## Posting an originating note' "$AD/skills/nostr/SKILL.md")
    has_warning=$(grep -c 'strongest \*active\* social signal' "$AD/skills/nostr/SKILL.md")
    if [ "$has_section" = "1" ] && [ "$has_warning" = "1" ]; then
        echo "ok: $u SKILL.md has note section + originating-signal warning"
    else
        echo "FAIL: $u SKILL.md missing note section -- re-run step 2"
    fi
done

# 3. Negative-path smokes (no network, no publish):
#    missing body -> missing-body
sudo -Hu fagents "$CLI_DIR/nostr.mjs" note 2>/dev/null | python3 -c "
import json, sys
try:
    d = json.loads(sys.stdin.read().strip())
    print('ok: missing body rejected as missing-body' if d.get('error') == 'missing-body' else f'FAIL: unexpected: {d}')
except Exception as e:
    print(f'FAIL: malformed: {e}')
"

#    bad topic (whitespace) -> bad-topic-format
sudo -Hu fagents "$CLI_DIR/nostr.mjs" note --tag 'has spaces' 'hi' 2>/dev/null | python3 -c "
import json, sys
try:
    d = json.loads(sys.stdin.read().strip())
    print('ok: whitespace topic rejected as bad-topic-format' if d.get('error') == 'bad-topic-format' else f'FAIL: unexpected: {d}')
except Exception as e:
    print(f'FAIL: malformed: {e}')
"
```

Don't include a live `note <body>` smoke -- that would publish a real public note to public relays. Manual dev-side smoke (against a throwaway nsec) is documented in the impl notes.

## Notes

- **Originating notes are the strongest *active* broadcast in the agent's toolkit.** Operators should monitor the agent's npub timeline post-deploy and intervene at the prompt/skill level if it posts garbage or content that looks like a paraphrase of upstream `<untrusted>` material without the SKILL's required pause-trigger acknowledgement.
- **No NOSTR_NOTE_ALLOWED_TOPICS by design** -- the skill carries the trust posture, same as reply / like / profile / follow.
- **Manual dev-side smoke** performed against damus.io / nos.lol / relay.primal.net with a throwaway nsec: posted a `--tag test` note, verified it landed on Damus + nostr.band.
- **null-byte test gap**: Node `child_process.spawn` blocks null-byte argv (`ERR_INVALID_ARG_VALUE`), so the test suite can't exercise the `null-byte-in-body` code path from the CLI. The check stays in code for protection against programmatic invocation.
