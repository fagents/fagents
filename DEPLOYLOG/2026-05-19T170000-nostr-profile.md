## What changed

Previous DEPLOYLOG shipped `nostr.mjs reply`. This one shipps the natural follow-up: agents can now set their own Nostr profile metadata (name, bio, avatar, etc) so they appear as named, identified npubs to other Nostr clients when they reply, not as anonymous hex pubkeys.

```
nostr.mjs profile set [--name <s>] [--about <s>] [--picture <url>] \
                      [--banner <url>] [--nip05 <s>] [--lud16 <s>] \
                      [--website <url>] [--replace]
nostr.mjs profile get [<npub>]
```

The CLI handles all NIP-01 kind:0 plumbing. `set` defaults to MERGE -- fetches the agent's current kind:0 across all relays, cleans the existing content through the same validators as new input, layers new fields on top, signs and republishes. `--replace` skips the merge and publishes only the specified fields. `get` with no arg reads the agent's own profile; `get <npub>` reads anyone else's (treat the response as `<untrusted>` -- same posture as search results).

**This is the third feature where the agent's nsec produces public content tied to its npub.** kind:1 reply was the second; kind:10050 inbox-list was the first. Profile metadata is semi-permanent: kind:0 is replaceable so the LATEST wins on relays, but old versions stay cached in clients and get screenshotted/quoted around. The skill description explicitly warns the agent about this softer-than-reply-but-still-real permanence.

Defenses at the CLI:
- **Replaceable-event semantics handled correctly**: `resolveProfile` is a COLLECTOR, not first-wins. Gathers every verified matching kind:0 from all relays until each settles, then picks the highest `created_at` (lexicographic `id` tiebreaker). First-wins would risk merging on top of stale metadata if a slow relay had the newer version.
- **URL fields are strictly canonical**: `--picture` / `--banner` / `--website` must parse via `new URL()`, have `http(s)` protocol, contain no whitespace/control chars, AND be byte-identical after `sanitizeText` (no silent strip of invisible Unicode -- URLs are signed into the public profile and rendered as clickable links, so smuggling there is high-impact).
- **Handle fields use the same canonical bar**: `--nip05` / `--lud16` reject smuggled invisible Unicode outright (consistent with URLs, since handles are identity-tied + cached the same way).
- **Merge-base cleanup**: existing profile content runs through `cleanProfileMetadata` before re-signing. Unknown keys, oversized strings, malformed URLs, pre-existing smuggling from another client all dropped -- the agent never re-signs garbage someone else left under its nsec.
- **`get` on other npubs returns the same cleaned shape**: only v1 keys, all strings re-validated. No nested-object leak.
- **Parser hardening**: arg values that look like the next flag (start with `--`) are rejected at the shift point. Without this, `profile set --name --replace` would consume `--replace` as the name string and publish `{"name":"--replace"}`.

No operator-side allow-list on profile content: by design (per user). The skill description carries the trust posture.

Tests: 56 new vitest-style assertions in `test_nostr.mjs` (groups 74-95). 221/221 PASS.

Out of scope (deferred): NIP-05 DNS verification, Lightning address verification, profile picture upload/hosting, NIP-39 external identity proofs, `profile delete` (kind:5 deletion semantics are weak in clients).

## Prerequisites

- No new runtime deps.
- No new env vars. `profile` uses the existing `NOSTR_RELAYS` from `nostr.env` for both resolve and publish.

## Setup steps

All commands run as root on the fagents host.

```bash
INFRA_USER="fagents"
INFRA_HOME=$(eval echo "~$INFRA_USER")
CLI_DIR="$INFRA_HOME/workspace/fagents-cli"
```

### 1. Preflight chown + pull fagents-cli

Per the DEPLOYLOG README template (`3c03acf`):

```bash
sudo chown -R "$INFRA_USER:fagent" "$INFRA_HOME/repos"
sudo chown -R "$INFRA_USER:fagent" "$INFRA_HOME/workspace"
sudo -Hu "$INFRA_USER" git -C "$CLI_DIR" pull origin main
```

No `npm install` (no new deps).

### 2. Re-render the nostr skill for each agent

```bash
for COMMS_USER in ftf ftl ftw; do
    AGENT_DIR="$INFRA_HOME/.agents/$COMMS_USER"
    [ -d "$AGENT_DIR/skills/nostr" ] || continue   # skip agents without Nostr DMs
    sudo sed "s|__CLI_DIR__|$CLI_DIR|g" "$CLI_DIR/nostr/SKILL.md" \
        | sudo tee "$AGENT_DIR/skills/nostr/SKILL.md" >/dev/null
    sudo chown "$INFRA_USER:fagent" "$AGENT_DIR/skills/nostr/SKILL.md"
    sudo chmod 644 "$AGENT_DIR/skills/nostr/SKILL.md"
done
```

Existing sudoers rule (`sudo -u fagents $CLI_DIR/nostr.mjs *`) covers the new `profile` subcommand -- no sudoers change required.

### 3. No daemon restart

`nostr.mjs serve` is unchanged. `profile set/get` are one-shot CLI invocations.

## Doctor

```bash
INFRA_HOME=$(eval echo "~fagents")
CLI_DIR="$INFRA_HOME/workspace/fagents-cli"

# 1. New subcommand is in help output
sudo -Hu fagents "$CLI_DIR/nostr.mjs" help | python3 -c "
import json, sys
cmds = json.load(sys.stdin)['commands']
ok_set = any(c.startswith('profile set') for c in cmds)
ok_get = any(c.startswith('profile get') for c in cmds)
print('ok: profile set + get in help' if ok_set and ok_get else 'FAIL: profile commands missing')
"

# 2. Each agent's installed SKILL.md has the new section + permanence note
for u in ftf ftl ftw; do
    AD="$INFRA_HOME/.agents/$u"
    [ -f "$AD/skills/nostr/SKILL.md" ] || continue
    has_section=$(grep -c '^## Managing your profile' "$AD/skills/nostr/SKILL.md")
    has_perm=$(grep -c 'softer than reply, still real' "$AD/skills/nostr/SKILL.md")
    if [ "$has_section" = "1" ] && [ "$has_perm" = "1" ]; then
        echo "ok: $u SKILL.md has profile section + permanence note"
    else
        echo "FAIL: $u SKILL.md missing profile section -- re-run step 2"
    fi
done

# 3. Parser hardening smoke: --name --replace must reject before
#    publish (no network call needed; arg parser catches it).
sudo -Hu fagents "$CLI_DIR/nostr.mjs" profile set --name --replace 2>/dev/null | python3 -c "
import json, sys
try:
    d = json.loads(sys.stdin.read().strip())
    print('ok: --name --replace rejected as bad-name-empty' if d.get('error') == 'bad-name-empty' else f'FAIL: unexpected: {d}')
except Exception as e:
    print(f'FAIL: malformed: {e}')
"
```

Don't include a live `profile set` step in the doctor -- it would write a real kind:0 to public relays. If you want a live verification, do it once manually with intentional content, not as a recurring doctor check.

No daemon restart needed. Any kind:0 events already published cannot be unpublished -- relays don't honor kind:5 deletions reliably. The replaceable-event semantics do mean a later `profile set --replace` with empty/clean content effectively hides the bad version on most clients, but old caches are forever.

## Notes

- **Profile content is permanent.** Like reply, but softer. Old versions stay in client caches and quotes. Agents should think before publishing.
- **No NOSTR_PROFILE_ALLOWED_FIELDS allow-list by design.** Per user. The skill carries the trust posture.
- **Manual dev-side smoke** was performed against damus.io / nos.lol / relay.primal.net: `set` published cleanly, `get` (own) read back the published content, `get` of Juho's real npub returned his actual profile cleaned through the v1 allow-list, `set --picture javascript:...` rejected, `set --name --replace` rejected (parser hardening), `set --nip05 foo\u{200B}@bar.com` rejected (handle smuggling).
- **Operator-side bulk set** isn't built in. If you want to seed a profile during install, just call `sudo -Hu fagents $CLI_DIR/nostr.mjs profile set ...` directly after step 2.
