## What changed

Previous DEPLOYLOG shipped `nostr.mjs follow`. This is the natural follow-up: the agent can now publish a public "+1" reaction to any kind:1 note via the standard NIP-25 kind:7 event shape.

```
nostr.mjs like <note-id-or-bech32>
```

Accepts raw 64-hex, `note1...`, or `nevent1...`. Resolves the target kind:1 via the existing `resolveEvent` (which already enforces `verifyEvent` + id match + kind:1 filter), then publishes a kind:7 with content `"+"` and tags `[["e", id], ["p", resolved-author], ["k", "1"]]`. NIP-25 recommended shape, no embellishments.

Scope deliberately minimal (per COORDINATE):
- Content is hardcoded `"+"`. No `--emoji` flag, no shortcode reactions.
- Target kind is **kind:1 text notes only**. Resolver's filter surfaces anything else as `event-not-found` (not a separate code).
- **No** `unlike` / `like remove` -- kind:5 deletions are unreliable across relays. Once liked, the kind:7 stays.
- **No** dedup. Kind:7 is regular (not replaceable). Re-running `like <same-id>` publishes a second kind:7; relays + clients dedup on display.

Defenses at the CLI:
- **Target decoder is strict**: new `decodeEventReference(raw)` accepts ONLY raw 64-hex / `note1` / `nevent1`. Pre-filters by prefix so a stray `npub1` / `nsec1` / `naddr1` never reaches `nip19.decode`. Returns null for everything else -> `bad-target-event-id`. Tests 144 and 145 cover this through the CLI surface (the CLI is a script with no exports).
- **p-tag derived from the RESOLVED, signature-verified event** -- NEVER from the caller's input. `nevent1` carries an optional embedded `author` hint; we deliberately ignore it. A hostile actor crafting an `nevent1` that points at a real note but lies about the author cannot trick the agent into endorsing the wrong person. Test 139 enforces this against a deliberately-mismatched author hint.
- **Strict argv**: `missing-target-event-id`, `unexpected-extra-args`, and `unknown-flag-<name>` all error BEFORE any network call. Tests 136-138 + the `recvReqs.length === 0` assertion verify zero REQ frames are sent for rejected inputs.
- **e-tag lowercase-hex enforced** via `normHexId` (defensive -- `resolveEvent` already validates, but tag content is always normalized).
- **No self-like gate**: self-likes are allowed but pointless (most clients hide them anyway). The skill description carries the operator-side trust posture, same as reply and profile.

Tests: 32 new vitest-style assertion blocks (test_nostr.mjs groups 129-145) covering happy paths for all three input formats, the p-tag derivation invariant, the bad-sig kind:1 rejection path, all argv error codes, decoder rejection of `npub1`/`nsec1`/`naddr1`, and bad-checksum bech32 try/catch path. Some blocks have more sub-assertions than budgeted so the actual count is higher than the plan's 323 target: **335/335 PASS** (up from 291).

Out of scope (deferred):
- `--emoji` / shortcode reactions
- Liking long-form (kind:30023), reposts (kind:6), or any non-kind:1 target
- `unlike` via kind:5
- Reaction-count queries (separate read-side feature if ever needed)

## Prerequisites

- No new runtime deps.
- No new env vars. `like` uses the existing `NOSTR_RELAYS` from `nostr.env`.

## Setup steps

All commands run as root on the fagents host.

```bash
INFRA_USER="fagents"
INFRA_HOME=$(eval echo "~$INFRA_USER")
CLI_DIR="$INFRA_HOME/workspace/fagents-cli"
```

### 1. Preflight chown + pull fagents-cli

Per the DEPLOYLOG README template (`3c03acf`):

```bash
sudo chown -R "$INFRA_USER:fagent" "$INFRA_HOME/repos"
sudo chown -R "$INFRA_USER:fagent" "$INFRA_HOME/workspace"
sudo -Hu "$INFRA_USER" git -C "$CLI_DIR" pull origin main
```

No `npm install` (no new deps).

### 2. Re-render the nostr skill for each agent

```bash
for COMMS_USER in ftf ftl ftw; do
    AGENT_DIR="$INFRA_HOME/.agents/$COMMS_USER"
    [ -d "$AGENT_DIR/skills/nostr" ] || continue
    sudo sed "s|__CLI_DIR__|$CLI_DIR|g" "$CLI_DIR/nostr/SKILL.md" \
        | sudo tee "$AGENT_DIR/skills/nostr/SKILL.md" >/dev/null
    sudo chown "$INFRA_USER:fagent" "$AGENT_DIR/skills/nostr/SKILL.md"
    sudo chmod 644 "$AGENT_DIR/skills/nostr/SKILL.md"
done
```

Existing sudoers rule (`sudo -u fagents $CLI_DIR/nostr.mjs *`) covers the new `like` subcommand.

### 3. No daemon restart

`nostr.mjs serve` is unchanged. `like` is a one-shot CLI invocation.

## Doctor

```bash
INFRA_HOME=$(eval echo "~fagents")
CLI_DIR="$INFRA_HOME/workspace/fagents-cli"

# 1. like subcommand visible in help output
sudo -Hu fagents "$CLI_DIR/nostr.mjs" help | python3 -c "
import json, sys
cmds = json.load(sys.stdin)['commands']
checks = [c for c in cmds if c.startswith('like ')]
print(f'ok: like subcommand in help' if len(checks) == 1 else f'FAIL: expected 1 like entry, got {len(checks)}')
"

# 2. Each agent's installed SKILL.md has the new section + the endorsement warning
for u in ftf ftl ftw; do
    AD="$INFRA_HOME/.agents/$u"
    [ -f "$AD/skills/nostr/SKILL.md" ] || continue
    has_section=$(grep -c '^## Liking a note' "$AD/skills/nostr/SKILL.md")
    has_warning=$(grep -c 'public endorsement of the note' "$AD/skills/nostr/SKILL.md")
    if [ "$has_section" = "1" ] && [ "$has_warning" = "1" ]; then
        echo "ok: $u SKILL.md has like section + endorsement warning"
    else
        echo "FAIL: $u SKILL.md missing like section -- re-run step 2"
    fi
done

# 3. Negative-path smokes (no network, no publish):
#    no positional -> missing-target
sudo -Hu fagents "$CLI_DIR/nostr.mjs" like 2>/dev/null | python3 -c "
import json, sys
try:
    d = json.loads(sys.stdin.read().strip())
    print('ok: missing positional rejected as missing-target-event-id' if d.get('error') == 'missing-target-event-id' else f'FAIL: unexpected: {d}')
except Exception as e:
    print(f'FAIL: malformed: {e}')
"

#    bad bech32 -> bad-target-event-id (also exercises the npub1 rejection branch)
SELF_NPUB=$(sudo -Hu fagents "$CLI_DIR/nostr.mjs" whoami | python3 -c "import json,sys; print(json.load(sys.stdin)['npub'])")
sudo -Hu fagents "$CLI_DIR/nostr.mjs" like "$SELF_NPUB" 2>/dev/null | python3 -c "
import json, sys
try:
    d = json.loads(sys.stdin.read().strip())
    print('ok: npub1 input rejected as bad-target-event-id' if d.get('error') == 'bad-target-event-id' else f'FAIL: unexpected: {d}')
except Exception as e:
    print(f'FAIL: malformed: {e}')
"
```

Don't include a live `like <real-note-id>` smoke -- that would publish a real reaction to a real note on public relays. Manual dev-side smoke (against a throwaway nsec) is documented in the impl notes.

```bash
cd "$CLI_DIR" && sudo -Hu "$INFRA_USER" git revert --no-edit addbadb
for u in ftf ftl ftw; do
    AD="$INFRA_HOME/.agents/$u"
    [ -d "$AD/skills/nostr" ] || continue

        | sudo tee "$AD/skills/nostr/SKILL.md" >/dev/null

```

No daemon restart for revert. Any kind:7 events already published cannot be cleanly unpublished (kind:5 deletions are unreliable). The skill text warns the agent about this -- a like is effectively permanent.

## Notes

- **Reactions are public + permanent.** Weaker social signal than a follow (you're endorsing one note, not the author wholesale) but stronger than a reply (no body for nuance -- just `"+"`). Operators should monitor the agent's npub reaction stream post-deploy and intervene at the prompt/skill level if it likes adversarial content.
- **No NOSTR_LIKE_ALLOWED_TARGETS by design** -- skill carries the trust posture, same as reply / profile / follow.
- **Manual dev-side smoke** was performed against damus.io / nos.lol / relay.primal.net with a throwaway nsec: liked a real test note via `note1`, `nevent1`, and raw hex; published kind:7 appeared on the target's reaction list in Damus + Amethyst.
- **Decoder rejection coverage**: `decodeEventReference` rejects `npub1`, `nsec1`, `naddr1`, bad-prefix, and bad-checksum bech32 BEFORE any network call -- confirmed via tests 144 and 145 + `recvReqs.length === 0`.
