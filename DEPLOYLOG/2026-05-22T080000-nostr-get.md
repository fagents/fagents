## What changed

Previous DEPLOYLOG shipped `nostr.mjs repost`. This is triage item #3 of the original four-feature triage: the agent now has a public read primitive that fetches a single event by id. With this, the read surface covers both the bulk-discovery shape (`search`) and the targeted-fetch shape (`get`).

```
nostr.mjs get <event-id-or-bech32> [--kind <n>]
```

Read-only. Accepts raw hex / `note1` / `nevent1` via the existing `decodeEventReference`. Any-kind by default because the NIP-01 event hash already binds kind. Optional `--kind <n>` is a safety assertion -- if provided, the relay-side REQ filter narrows to `kinds:[n]` AND the post-receive check rejects events of the wrong kind. Output is `search`'s per-event JSON shape PLUS a `sig` field (single-event reads may be forwarded / cached / re-verified downstream, where the signature is load-bearing; bulk `search` omits sig because it's per-event byte-noise).

This cycle also includes a **load-bearing refactor**: `resolveEvent(id, relays, timeoutMs, expectedKind)` now takes the kind assertion as an explicit required parameter. The function throws synchronously if `expectedKind === undefined`, so any unmigrated caller fails loudly at first invocation. The three existing callers (`doReply`, `doLike`, `doRepost`) were migrated to pass `1` explicitly. Behavior is unchanged for all three -- the 50+ pre-existing reply/like/repost tests + new wire-level filter assertions (tests 56g / 129j / 168m verify each migrated handler's REQ filter contains `kinds:[1]`) confirm the migration is complete.

Defenses at the CLI for the new `get`:
- **Target decoder reuses existing `decodeEventReference`** -- rejects `npub1`/`nsec1`/`naddr1`/bad-checksum bech32 BEFORE any network call.
- **`--kind` strict canonical decimal** -- `parseInt('1abc', 10)` silently truncates to `1` and would let `--kind 1abc` slip through; the `String(n) === v` check catches that. Range `[0, 65535]` covers conventional Nostr kind space. Tests 202a-c + 203a-b cover the rejection paths.
- **`resolveEvent` throws on undefined expectedKind** -- developer-safety guard. Not directly testable from CLI level (nostr.mjs has no export seam), but the 50+ existing reply/like/repost tests + new wire-level filter assertions guarantee no unmigrated caller in practice.
- **Output sanitization** -- `content` via `sanitizeText`, `tags` via `sanitizeTags`. Same posture as `search` results. The skill marks `get` output as `<untrusted>`.
- **No nsec** -- `get` is read-only. The handler doesn't call `decodeNsec` or `loadEnv().nsec`. Only `env.relays` is touched.

Tests: 22 new test blocks (groups 187-210) for `get` plus 3 single-line REQ-filter assertions appended to the existing mainline tests for reply (56g), like (129j), and repost (168m). 58 new assertions total. **499/499 PASS** (up from 441). Tests 209-210 specifically verify the relay-side REQ filter shape: 209 confirms the any-kind path emits no `kinds` field, 210 confirms `--kind 7` emits `kinds:[7]`. The 56g/129j/168m assertions verify each migrated handler's REQ filter now contains `kinds:[1]` (proves the explicit `1` argument flows through to the resolver's REQ filter for every migrated caller).

Out of scope (deferred):
- `naddr1` (replaceable-event by (kind, pubkey, d-tag)) -- different query shape, separate cycle
- Multi-id batch fetch
- Streaming follow / live-update mode
- Replaceable-event "latest" semantics (use existing `profile get` / `follow list` / etc for kind:0/3/10050)
- Triage item #4 (followers count for analytics) -- next cycle

## Prerequisites

- No new runtime deps.
- No new env vars. `get` uses the existing `NOSTR_RELAYS` from `nostr.env`. Optional `NOSTR_GET_TIMEOUT_MS` (default 5000) override.

## Setup steps

All commands run as root on the fagents host.

```bash
INFRA_USER="fagents"
INFRA_HOME=$(eval echo "~$INFRA_USER")
CLI_DIR="$INFRA_HOME/workspace/fagents-cli"
```

### 1. Preflight chown + pull fagents-cli

Per the DEPLOYLOG README template (`3c03acf`):

```bash
sudo chown -R "$INFRA_USER:fagent" "$INFRA_HOME/repos"
sudo chown -R "$INFRA_USER:fagent" "$INFRA_HOME/workspace"
sudo -Hu "$INFRA_USER" git -C "$CLI_DIR" pull origin main
```

No `npm install` (no new deps).

### 2. Re-render the nostr skill for each agent

```bash
for COMMS_USER in ftf ftl ftw; do
    AGENT_DIR="$INFRA_HOME/.agents/$COMMS_USER"
    [ -d "$AGENT_DIR/skills/nostr" ] || continue
    sudo sed "s|__CLI_DIR__|$CLI_DIR|g" "$CLI_DIR/nostr/SKILL.md" \
        | sudo tee "$AGENT_DIR/skills/nostr/SKILL.md" >/dev/null
    sudo chown "$INFRA_USER:fagent" "$AGENT_DIR/skills/nostr/SKILL.md"
    sudo chmod 644 "$AGENT_DIR/skills/nostr/SKILL.md"
done
```

Existing sudoers rule (`sudo -u fagents $CLI_DIR/nostr.mjs *`) covers the new `get` subcommand.

### 3. No daemon restart

`nostr.mjs serve` is unchanged. `get` is a one-shot CLI invocation. The resolveEvent refactor is internal -- the daemon doesn't call resolveEvent (it consumes NIP-17 gift wraps via the long-running socket pool, not the one-shot REQ path).

## Notes

- **The resolveEvent refactor is the load-bearing change** behind this feature. Reply / like / repost continue to enforce kind:1 because they explicitly pass `1` to the resolver. The throw-on-undefined guard means any future caller that forgets to pass an expectedKind argument will fail loudly at first invocation, rather than silently widening behavior to accept any kind.
- **No NOSTR_GET_ALLOWED_KINDS by design** -- the skill carries the trust posture, same as search.
- **Manual dev-side smoke** performed against damus.io / nos.lol / relay.primal.net with a throwaway nsec: fetched a real kind:1 by raw hex + via note1 (both successful, output had `sig` field), fetched a real kind:0 profile by id without `--kind` (kind=0 returned), exercised `--kind 1` against a kind:0 target (rejected as `event-not-found`), exercised bad-kind-value (`1abc`) and missing-target rejection paths.
