## What changed

Previous DEPLOYLOG shipped `nostr.mjs profile`. This is the natural follow-up: who the agent pays attention to on Nostr. NIP-02 kind:3 is the "contact list" -- a replaceable event whose `tags` array lists every pubkey the agent follows, with optional relay-hint and petname per entry. Modern Nostr clients render this as the agent's following list.

```
nostr.mjs follow add <npub> [--petname "name"] [--relay wss-url]
nostr.mjs follow remove <npub>
nostr.mjs follow list [<npub>]
```

`add` is **per-field MERGE**: re-running with no flags (or with only one of the two optional flags) preserves whatever's stored for fields you didn't pass. `--replace` is intentionally not supported -- bulk-set semantics is deferred. To clear a field, use `follow remove` + `follow add` for a hard reset.

`remove` errors `not-following` if you're not following the target (no wasted publish).

`list` with no arg reads the agent's own follow list; `list <npub>` reads anyone else's (same `<untrusted>` posture as `profile get` / search results).

**This is the fourth feature where the agent's nsec produces public content tied to its npub** (after kind:10050 inbox-list, kind:1 reply, kind:0 profile). Following is the strongest social signal in the toolkit -- stronger than a reply because the agent is publicly *endorsing* the person. The skill description explicitly emphasizes "don't follow npubs you can't identify" and carries forward the pause-trigger anchor from the reply cycle ("found this pubkey in untrusted content").

Defenses at the CLI:
- **Target validation**: npub decoded to lowercase 64-hex via `decodeNpub`. Bad input -> `bad-target-npub`.
- **Self-follow refused at the gate**: `targetHex === myHex` -> `cannot-follow-self`. Plus `contacts.delete(myHex)` runs on every add/remove BEFORE signing, so any self-follow tag a prior client may have written into the kind:3 gets stripped on the next write. The no-self-follow invariant holds across re-signs, not just at the add gate.
- **Per-field merge**: re-adding an existing contact preserves stored `relay`/`petname` unless explicitly overridden via the corresponding flag. No silent clearing of metadata.
- **Replaceable-event freshness**: `resolveContactList` uses the same collector pattern as `resolveProfile` (shared via the new `resolveLatestReplaceable(authorHex, kind, relays, timeoutMs)` helper). Highest `created_at` wins across all relays, lexicographic `id` tiebreaker. First-wins would risk merging on top of stale state if a slow relay had the newer version.
- **Strict argv**: every subcommand rejects trailing positionals, unknown flags, and duplicate flags BEFORE any network call.
- **URL fields strict-canonical**: relay hints restricted to `wss:`/`ws:` schemes via `new URL()` + canonical-input check (no silent strip of invisible Unicode). Petnames capped at 100 chars + canonical + sanitized.
- **List output cleaned**: `parseContactList` drops malformed entries (non-hex pubkey, non-`p` tags, oversized fields, smuggled Unicode in petname) before the agent ever sees them.

Tests: 70 new vitest-style assertions in `test_nostr.mjs` (groups 96-128). 291/291 PASS.

The SIMPLIFY pass also consolidated three pieces of duplication across the test suite (resolveProfile/resolveContactList -> shared helper; three capture mocks -> one; four `runX` wrappers -> one). Public wrapper names preserved -- zero test call-site changes. Net ~95 lines saved.

## Setup steps

All commands run as root on the fagents host.

```bash
INFRA_USER="fagents"
INFRA_HOME=$(eval echo "~$INFRA_USER")
CLI_DIR="$INFRA_HOME/workspace/fagents-cli"
```

### 1. Preflight chown + pull fagents-cli

Per the DEPLOYLOG README template (`3c03acf`):

```bash
sudo chown -R "$INFRA_USER:fagent" "$INFRA_HOME/repos"
sudo chown -R "$INFRA_USER:fagent" "$INFRA_HOME/workspace"
sudo -Hu "$INFRA_USER" git -C "$CLI_DIR" pull origin main
```

No `npm install` (no new deps).

### 2. Re-render the nostr skill for each agent

```bash
for COMMS_USER in ftf ftl ftw; do
    AGENT_DIR="$INFRA_HOME/.agents/$COMMS_USER"
    [ -d "$AGENT_DIR/skills/nostr" ] || continue
    sudo sed "s|__CLI_DIR__|$CLI_DIR|g" "$CLI_DIR/nostr/SKILL.md" \
        | sudo tee "$AGENT_DIR/skills/nostr/SKILL.md" >/dev/null
    sudo chown "$INFRA_USER:fagent" "$AGENT_DIR/skills/nostr/SKILL.md"
    sudo chmod 644 "$AGENT_DIR/skills/nostr/SKILL.md"
done
```

Existing sudoers rule (`sudo -u fagents $CLI_DIR/nostr.mjs *`) covers the new `follow` subcommand.

### 3. No daemon restart

`nostr.mjs serve` is unchanged. `follow add/remove/list` are one-shot CLI invocations.

```bash
# 3. Negative-path smokes (no network, no publish):
#    self-follow rejected before any write

import json, sys
try:
    d = json.loads(sys.stdin.read().strip())
    print('ok: self-follow rejected as cannot-follow-self' if d.get('error') == 'cannot-follow-self' else f'FAIL: unexpected: {d}')
except Exception as e:
    print(f'FAIL: malformed: {e}')
"

#    strict argv rejects trailing positional
sudo -Hu fagents "$CLI_DIR/nostr.mjs" follow add "$SELF_NPUB" extra 2>/dev/null | python3 -c "
import json, sys
try:
    d = json.loads(sys.stdin.read().strip())
    # Either 'cannot-follow-self' (self check first) or 'unexpected-extra-args' --
    # both prove the CLI rejected the request before any network call.
    if d.get('error') in ('cannot-follow-self', 'unexpected-extra-args'):
        print(f'ok: rejected with {d[\"error\"]} before network')
    else:
        print(f'FAIL: unexpected: {d}')
except Exception as e:
    print(f'FAIL: malformed: {e}')
"
```

Don't include a live `follow add <real-npub>` smoke -- that would write a real kind:3 to public relays and add a follower the operator may not intend.

## Notes

- **Follow lists are public.** Stronger social signal than reply. Operators should monitor the agent's npub timeline post-deploy and intervene at the prompt/skill level if the agent follows pubkeys it shouldn't.
- **No NOSTR_FOLLOW_ALLOWED_TARGETS by design** -- skill carries the trust posture, same as reply + profile.
- **Manual dev-side smoke** was performed against damus.io / nos.lol / relay.primal.net with a throwaway nsec: add + list + list-juho + remove all worked end-to-end. The shared `resolveLatestReplaceable` helper exercises both `profile get` and `follow list` live -- both paths verified.
- **Per-field merge protects against silent metadata loss**: re-running `follow add <existing>` is now idempotent. An agent that re-adds someone without specifying `--petname` does not blank their previously stored petname.
- **Self-follow strip across writes**: even if a prior client (or an older version of the CLI before this fix) ever wrote myHex into the kind:3, this version strips it on every add/remove re-sign.
