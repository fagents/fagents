# Nostr DMs (NIP-17) — Deploy to Existing Installation

**Date:** 2026-05-17
**Repos changed:** fagents-cli, fagents-autonomy, fagents

## Commits to pull

```
fagents-cli:       <NOSTR-CLI-SHA>      Add nostr.mjs (NIP-17 DMs) + tests + nostr/SKILL.md
fagents-autonomy:  <AUTONOMY-SHA>       Daemon: collect_nostr + ensure_nostr_serve + cadence + test_daemon.sh
fagents:           <FAGENTS-SHA>        Installer: Nostr prompt + nostr.env + sudoers + skill install
```

New installs get this automatically via the installer (`NOSTR_ENABLE=1` env var in NONINTERACTIVE mode, or interactive prompt). This doc is for existing deployments.

## What changed

- **fagents-cli** — new `nostr.mjs` (NIP-17 sealed-sender DMs over Nostr relays). Subcommands: `login` (generate/import nsec, MERGES env), `logout`, `serve` (long-running relay subscriber + outbox sender), `poll` (drain spool), `send <npub> <body>`, `whoami`. Uses `nostr-tools` 2.23.3 + `ws` 8.18.0 (dev). New `nostr/SKILL.md`. 68 tests.
- **fagents-autonomy** — `daemon.sh` adds `collect_nostr()`, `ensure_nostr_serve()`, `NOSTR_CADENCE` (default 3s), `LAST_NOSTR_CHECK`, and `NOSTR_DISABLE=1` opt-out. Inbox entries get `source: "nostr"`, raw body, `trusted: false` (read_inbox wraps in <untrusted>). 19 new daemon tests.
- **fagents** — installers (`install-team.sh`, `install-team-macos.sh`) add the Nostr prompt block + env-write + sudoers rule. `install-agent.sh` skill list now includes `nostr`. NONINTERACTIVE env vars: `NOSTR_ENABLE=1`, `NOSTR_AGENTS_INPUT="..."`, `NOSTR_RELAYS_INPUT="wss://relay.damus.io,wss://nos.lol"`, `NOSTR_NSEC_INPUT_<AGENT>=nsec1...`, `NOSTR_ALLOWED_NPUBS_INPUT_<AGENT>="npub1...,npub1..."`.

## Prerequisites

- **Node.js >= 20.19** on the host. `nostr-tools` transitive deps (`@noble/ciphers`, `@noble/curves`, `@noble/hashes`) declare `engines: ">= 20.19.0"`. Older Node will install but `nostr.mjs serve` will crash. Both installers now version-check and skip Nostr setup with a warning if Node is too old.
- `nostr-tools@2.23.3` and `ws@8.18.0` will be installed via `npm install` (autonomous; step 4 below). 30-day-min age policy verified.
- One npub from each human / agent you want to receive DMs from. Without `NOSTR_ALLOWED_NPUBS` entries, inbound is fail-closed (everything dropped).

## Setup steps

All commands run as root on the fagents host.

```bash
INFRA_USER="fagents"
INFRA_HOME=$(eval echo "~$INFRA_USER")
CLI_DIR="$INFRA_HOME/workspace/fagents-cli"
```

### 1. Pull fagents-cli, fagents-autonomy, fagents

```bash
cd "$INFRA_HOME/workspace/fagents-cli" && sudo -Hu "$INFRA_USER" git pull
cd "$INFRA_HOME/workspace/fagents-autonomy" && sudo -Hu "$INFRA_USER" git pull
cd "$INFRA_HOME/workspace/fagents" && sudo -Hu "$INFRA_USER" git pull
```

### 2. Install Node deps (nostr-tools + ws)

```bash
cd "$CLI_DIR"
sudo -Hu "$INFRA_USER" npm install --production
```

Pre-existing Baileys (WhatsApp) advisories will show; not introduced by this change.

### 3. For each comms agent that should have Nostr DMs:

Pick the comms agent (e.g. `coo`, `engineer`, etc.). Substitute below.

```bash
COMMS_USER="coo"   # change per agent
AGENT_DIR="$INFRA_HOME/.agents/$COMMS_USER"

# Seed env with relays + (optional) allow-list.
sudo -Hu "$INFRA_USER" tee "$AGENT_DIR/nostr.env" >/dev/null <<'EOF'
NOSTR_RELAYS=wss://relay.damus.io,wss://nos.lol,wss://nostr.wine
NOSTR_ALLOWED_NPUBS=
EOF
sudo chmod 600 "$AGENT_DIR/nostr.env"

# Generate the agent's nsec (MERGES NSEC/NPUB into nostr.env, preserves RELAYS/ALLOWED).
# Add --nsec nsec1... to import an existing key instead of generating.
sudo -Hu "$INFRA_USER" "$CLI_DIR/nostr.mjs" --env-file "$AGENT_DIR/nostr.env" login

# Spool + outbox dirs (chmod 0700 owned by INFRA_USER).
sudo -Hu "$INFRA_USER" mkdir -p "$AGENT_DIR/nostr-spool" "$AGENT_DIR/nostr-outbox"

# Display the agent's npub. Share this with humans / other agents.
sudo -Hu "$INFRA_USER" "$CLI_DIR/nostr.mjs" --env-file "$AGENT_DIR/nostr.env" whoami
```

Output of `whoami` shows `{npub, relays, allowed_npubs_count}`. The `npub1...` is what you share.

### 4. Update sudoers so the agent can invoke nostr.mjs

```bash
COMMS_USER="coo"   # per agent

if [ -f "/etc/sudoers.d/${COMMS_USER}-telegram" ]; then
    existing=$(cat "/etc/sudoers.d/${COMMS_USER}-telegram")
    echo "${existing}, $CLI_DIR/nostr.mjs" > "/etc/sudoers.d/${COMMS_USER}-telegram"
    chmod 440 "/etc/sudoers.d/${COMMS_USER}-telegram"
else
    echo "$COMMS_USER ALL=($INFRA_USER) NOPASSWD: $CLI_DIR/nostr.mjs" > "/etc/sudoers.d/${COMMS_USER}-nostr"
    chmod 440 "/etc/sudoers.d/${COMMS_USER}-nostr"
fi
```

### 5. Install the nostr skill (one-time per agent)

The skill teaches the agent how to use the CLI.

```bash
mkdir -p "$AGENT_DIR/skills/nostr"
sed "s|__CLI_DIR__|$CLI_DIR|g" "$CLI_DIR/nostr/SKILL.md" > "$AGENT_DIR/skills/nostr/SKILL.md"
sudo chown -R "$INFRA_USER:fagent" "$AGENT_DIR/skills"
sudo chmod 644 "$AGENT_DIR/skills/nostr/SKILL.md"
```

### 6. Restart the agent's daemon

Self-restart (do NOT stop+start; daemon may be processing a turn):

```bash
sudo systemctl restart "fagents-agent@$COMMS_USER"
# Or whatever your daemon supervisor uses on this host.
```

Daemon will start `nostr serve` automatically on the first tick if `nostr.env` is present.

### 7. Add allow-listed senders

Have the human / other agent share their `npub1...`. Add it to `NOSTR_ALLOWED_NPUBS` in the agent's env file:

```bash
sudo -Hu "$INFRA_USER" sed -i 's|NOSTR_ALLOWED_NPUBS=.*|NOSTR_ALLOWED_NPUBS=npub1abc...,npub1def...|' "$AGENT_DIR/nostr.env"
# Restart serve to pick up the new list.
sudo systemctl restart "fagents-agent@$COMMS_USER"
```

Until at least one npub is in `NOSTR_ALLOWED_NPUBS`, ALL inbound DMs are dropped (fail-closed).

## Doctor

After deploy, verify:

```bash
# 1. nostr.mjs is on the host
ls -la "$CLI_DIR/nostr.mjs"

# 2. env file exists and is 0600
sudo ls -l "$AGENT_DIR/nostr.env"

# 3. agent can call nostr.mjs whoami via sudo (matches sudoers: direct exec,
#    not `node <path>`; pass --env-file explicitly because sudo strips env).
sudo -u "$COMMS_USER" sudo -u "$INFRA_USER" "$CLI_DIR/nostr.mjs" --env-file "$AGENT_DIR/nostr.env" whoami

# 4. daemon started nostr serve
sudo journalctl -u "fagents-agent@$COMMS_USER" --since "5 min ago" | grep -i nostr

# 5. allow-listed sender sends a DM via their client (Damus / Amethyst / Primal / etc.)
#    A new .queue/inbox/nostr-*.jsonl appears within NOSTR_CADENCE (3s) of receipt.
sudo ls -lt "$AGENT_DIR/.queue/inbox/" | grep nostr | head
```

## Rollback

If something breaks:

```bash
# 1. Disable serve startup
sudo systemctl set-environment NOSTR_DISABLE=1
sudo systemctl restart "fagents-agent@$COMMS_USER"

# 2. Or remove nostr.env entirely (daemon ignores when env file is absent)
sudo mv "$AGENT_DIR/nostr.env" "$AGENT_DIR/nostr.env.disabled"
sudo systemctl restart "fagents-agent@$COMMS_USER"
```

`nostr.mjs` and the sudoers entry can stay; they're dormant without `nostr.env`.

## Notes

- **Privacy: NIP-17 hides sender, not recipient.** The gift wrap's `p` tag uses your agent's main npub so relays can route. Relays see "this npub got a DM at time T", but not from whom or what. Body is E2E encrypted (NIP-44 v2).
- **Allow-list is hex-compared internally.** You give npub1... strings in the env; the CLI decodes them at startup. Re-decode happens on serve restart, not on every msg.
- **Per-agent identity.** Each agent gets its own nsec/npub. Agents don't share keys.
- **Public relays.** Default list is well-known free relays. Swap with private/paid relays via `NOSTR_RELAYS` if you need a smaller blast radius.
