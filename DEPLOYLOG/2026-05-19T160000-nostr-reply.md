## What changed

The previous DEPLOYLOG shipped `nostr.mjs search`. This one shipps the natural follow-up: agents can now post a kind:1 reply to a note they've discovered. The CLI handles NIP-10 thread plumbing; agents pass only the parent event id and the reply body.

```
nostr.mjs reply <parent-event-id> "<body>"
```

The CLI auto-resolves the parent via a one-shot REQ against `NOSTR_RELAYS` (validates signature + id match + kind:1), builds NIP-10 marker-style reply tags from the resolved parent, sanitizes the body for invisible Unicode, signs the kind:1 with the agent's nsec, and publishes to all relays (at-least-one-OK). Returns `{ok, id, parent, tags}` on success.

**This is the first feature where the agent's nsec produces public content tied to its npub.** NIP-17 DMs are sealed-sender (real identity hidden in the wrap), kind:10050 is trivial metadata, but a reply is permanent public content identity-bound to the agent. The skill documentation explicitly warns the agent that replies are forever, screenshot-able, and quoted by other clients. Operators should verify the warning landed in each agent's installed SKILL.md (doctor step below).

Defenses at the CLI:
- **Parent resolution is strict**: `verifyEvent(parent)` + `parent.id === requested-id` + `parent.kind === 1`. Rejects relay-fabricated frames (non-binding-filter attack) and replies to non-notes.
- **Tag construction is validated**: every `p` and `e` value carried forward from parent tags passes a `/^[0-9a-f]{64}$/i` check + lowercase normalisation. Malformed entries are dropped, never signed into our public reply (parent tag content is author-controlled even though the parent event is signed).
- **NIP-10 current spec**: marked e-tags use the 5-field `["e", id, relay-hint, marker, author]` shape. Relay hint is the relay that actually resolved the parent.
- **Outbound body is sanitized**: same regex as the email + search paths (zero-width / full `\p{Bidi_Control}` / variation selectors / tag block). If sanitization leaves an empty body, the CLI exits with `empty-body-after-sanitize` -- no signed empty kind:1 ever published.
- **Multi-relay cleanup**: a shared `raceRelays` helper closes EVERY ephemeral socket on first success / exhaustion / timeout. Pre-fix, silent peer sockets kept Node alive after stdout. Post-fix, the subprocess exits in ~150ms after first OK.

No operator-side allow-list on reply targets: by design (per user). The skill description carries the trust posture.

Tests: 46 new vitest-style assertions in `test_nostr.mjs` (groups 56-73). 165/165 PASS.

Out of scope (deferred): top-level notes (no parent), mentions outside reply chain, kind:5 deletions.

## Prerequisites

- No new runtime deps. `nostr-tools` + `ws` already pinned.
- No new env vars. Uses existing `NOSTR_RELAYS` from `nostr.env` for both parent resolution and publish.

## Setup steps

All commands run as root on the fagents host.

```bash
INFRA_USER="fagents"
INFRA_HOME=$(eval echo "~$INFRA_USER")
CLI_DIR="$INFRA_HOME/workspace/fagents-cli"
```

### 1. Preflight chown + pull fagents-cli

Per the DEPLOYLOG README template (broadened in `3c03acf`):

```bash
sudo chown -R "$INFRA_USER:fagent" "$INFRA_HOME/repos"
sudo chown -R "$INFRA_USER:fagent" "$INFRA_HOME/workspace"
sudo -Hu "$INFRA_USER" git -C "$CLI_DIR" pull
```

No `npm install` (no new deps).

### 2. Re-render the nostr skill for each agent

The `reply` subcommand documentation lives in `nostr/SKILL.md`. Render so the new section becomes agent-visible:

```bash
for COMMS_USER in ftf ftl ftw; do
    AGENT_DIR="$INFRA_HOME/.agents/$COMMS_USER"
    [ -d "$AGENT_DIR/skills/nostr" ] || continue   # skip agents without Nostr DMs
    sudo sed "s|__CLI_DIR__|$CLI_DIR|g" "$CLI_DIR/nostr/SKILL.md" \
        | sudo tee "$AGENT_DIR/skills/nostr/SKILL.md" >/dev/null
    sudo chown "$INFRA_USER:fagent" "$AGENT_DIR/skills/nostr/SKILL.md"
    sudo chmod 644 "$AGENT_DIR/skills/nostr/SKILL.md"
done
```

The existing sudoers rule (`sudo -u fagents $CLI_DIR/nostr.mjs *`) covers the new `reply` subcommand -- no sudoers change required.

### 3. No daemon restart

`nostr.mjs serve` is unchanged. `reply` is a one-shot CLI invocation. No restart of `fagents` systemd unit required.

## Notes

- **Replies are forever.** Once an agent posts a reply, the kind:1 event is signed by the agent's nsec and propagated across relays. Other clients screenshot. There is no edit. Operators should monitor the agent's npub timeline post-deploy and intervene at the prompt/skill level if the agent's reply quality is wrong.
- **NIP-10 marker style only.** Some old clients use the positional pre-marker convention. Most modern clients (Damus, Amethyst, Primal) handle both. A small slice of clients may mis-thread; acceptable.
- **No NOSTR_REPLY_ALLOWED_TARGETS allow-list** by design. Reply gating is purely skill-level. If post-deploy experience surfaces a need to constrain reply targets per agent, that's a follow-up DEPLOYLOG.
- **Live-smoke during manual review** was performed dev-side against damus.io / nos.lol / primal.net (kai's local debug nsec): real parent resolved, reply published with correct 5-field e-tag and relay hint pointing to the actual delivering relay. Subprocess exited in 0.6s wall time post-success.
