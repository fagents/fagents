**Date:** 2026-05-19
**Repos changed:** fagents-cli

## What changed

Agents can now query the public Nostr timeline for hashtags or keywords. This is independent of NIP-17 DMs (which were the previous Nostr surface) -- the existing DM commands are unchanged, and there is no shared state. A team asked for the ability to discover public-timeline discussions; this delivers it.

- **fagents-cli** -- new `search` subcommand on `nostr.mjs`:
  - `nostr.mjs search --tag <topic> [--limit n] [--since 7d]` (NIP-01 `#t` filter; works on every relay)
  - `nostr.mjs search "<keyword>" [--limit n] [--since 24h]` (NIP-50 search filter; only relays that opt in)
  - Optional flags: `--kind <n>` (default 1), `--limit <n>` (1-100, default 20), `--since <duration>` (`30s`/`5m`/`2h`/`7d`/plain seconds), `--author <npub>`
  - Output: one JSON event per line on stdout, sorted newest-first. Each line has `{kind, id, pubkey, npub, created_at, content, tags}`.
  - Optional `NOSTR_SEARCH_RELAYS` env var (process env or env-file) overrides `NOSTR_RELAYS` for the search path only. Lets operators point search at NIP-50-capable relays (`wss://relay.nostr.band` etc) without changing the DM relay set.
- **fagents-cli** -- updated `nostr/SKILL.md`:
  - New "Public-timeline search" section + commands listing.
  - Trust warning: results have NO allow-list -- agents must treat both `content` AND every `tags[i][j]` as `<untrusted>`.
- Tests: 36 new vitest-style assertions in `test_nostr.mjs` (search hashtag + keyword + interspersed flags + dedup + verifyEvent + sanitization + timeout + flag validation + relay precedence + NOTICE-before-EVENT survival + stderr log-injection). 119/119 PASS.

Architecture choice: same CLI as the DM commands (one-CLI-per-protocol pattern, mirrors `x.sh search` + `post`). Code paths for search and DMs do NOT share state -- search opens ephemeral WebSockets, doesn't touch the long-running `serve` process.

Defenses on emitted events:
- `verifyEvent` rejects relay-fabricated frames before dedup.
- `sanitizeText` / `sanitizeTags` strip the same invisible-Unicode classes the email sanitizer strips (zero-width / full `\p{Bidi_Control}` / variation selectors / tag block).
- Relay-controlled `CLOSED reason` and `NOTICE msg` strings pass through `truncate()` before stderr write (no log-line injection).

Out of scope: NIP-3 follows, kind:0 profile metadata, pagination cursors, NIP-11 auto-discovery of search-capable relays.

## Prerequisites

- No new runtime deps. `nostr-tools` 2.23.3 + `ws` are already pinned for the DM path.
- No new env vars are required. `NOSTR_SEARCH_RELAYS` is optional; if absent, search uses the same `NOSTR_RELAYS` as DMs.

## Setup steps

All commands run as root on the fagents host.

```bash
INFRA_USER="fagents"
INFRA_HOME=$(eval echo "~$INFRA_USER")
CLI_DIR="$INFRA_HOME/workspace/fagents-cli"
```

### 1. Pull fagents-cli

Preflight chown is included in the DEPLOYLOG README template (commit `67762fe`) -- if you're following that template, .git ownership is already handled. For ad-hoc deploys:

```bash
sudo chown -R "$INFRA_USER:fagent" "$CLI_DIR/.git"
cd "$CLI_DIR" && sudo -Hu "$INFRA_USER" git pull
```

No `npm install` needed (no new deps).

### 2. For each comms agent already configured for Nostr DMs

Re-render the nostr skill file so the new search section becomes agent-visible. The CLI updates pick up automatically on next invocation, but the SKILL.md is a static file the agent reads on session start.

```bash
COMMS_USER="coo"   # change per agent (ftf, ftl, ftw, etc)
AGENT_DIR="$INFRA_HOME/.agents/$COMMS_USER"

# Re-render the skill (idempotent; preserves any operator-customised content
# is N/A here since this skill is a generated file).
sudo sed "s|__CLI_DIR__|$CLI_DIR|g" "$CLI_DIR/nostr/SKILL.md" > "$AGENT_DIR/skills/nostr/SKILL.md"
sudo chown "$INFRA_USER:fagent" "$AGENT_DIR/skills/nostr/SKILL.md"
sudo chmod 644 "$AGENT_DIR/skills/nostr/SKILL.md"
```

Repeat for each agent. The existing sudoers rule (`sudo -u fagents $CLI_DIR/nostr.mjs *`) already covers the new `search` subcommand -- no sudoers change required.

### 3. (Optional) Point search at a NIP-50-capable relay

If operators want keyword search to work, set `NOSTR_SEARCH_RELAYS` in each agent's nostr.env. Hashtag-only search works on every relay; keyword search needs NIP-50.

Reachability note from the dev-side smoke (2026-05-19): of the well-known free relays, only `wss://relay.nostr.band` advertises NIP-50. From imagine-emerge it may reach others. Confirm with a probe before committing to a list.

```bash
COMMS_USER="coo"
AGENT_DIR="$INFRA_HOME/.agents/$COMMS_USER"

# Append (or update) the search-relay override. Standard env-file format.
sudo -Hu "$INFRA_USER" tee -a "$AGENT_DIR/nostr.env" >/dev/null <<'EOF'
NOSTR_SEARCH_RELAYS=wss://relay.nostr.band,wss://relay.primal.net
EOF
sudo chmod 600 "$AGENT_DIR/nostr.env"
```

If you skip this step, agents calling `search "keyword"` will get fast-fail NOTICE/CLOSED diagnostics in stderr from relays that don't support NIP-50. Hashtag mode still works.

### 4. No daemon restart

`nostr.mjs serve` is unchanged -- the new `search` subcommand runs as a one-shot CLI invocation. No restart of `fagents` systemd unit required.

```bash
            || echo "FAIL: $u SKILL.md missing search section -- re-run step 2"

# 3. Live smoke: hashtag search returns at least one event (popular tag, short window)
sudo -u fagents "$CLI_DIR/nostr.mjs" search --tag bitcoin --limit 1 --since 1h | head -1 | python3 -c "
import json, sys
line = sys.stdin.read().strip()
if not line:
    print('WARN: no events returned (relay may be slow; not necessarily broken)')
else:
    try:
        ev = json.loads(line)
        assert ev.get('kind') and ev.get('id') and ev.get('content') is not None
        print('ok: live hashtag search returned a well-formed event')
    except Exception as e:
        print(f'FAIL: malformed output: {e}')
"
```

## Notes

- **Public search has no identity gate.** Unlike DMs (gated by NOSTR_ALLOWED_NPUBS), search results are unauthenticated public-timeline content. The skill description directs agents to treat `content` AND `tags` as `<untrusted>` -- no further enforcement on the daemon side. Trust posture documented in SECURITY.md (workspace root, tandem-reviewed).
- **NIP-50 relay landscape is patchy.** Mainstream relays (damus.io, nos.lol, primal.net) reject the `search:` filter. The skill points operators at known NIP-50-capable relays via `NOSTR_SEARCH_RELAYS`.
- **No new DEPLOYLOG required for the routine pull.** The SECURITY.md change lives in the fagents workspace root (tandem-reviewed docs, not deployed). Only fagents-cli has a deploy footprint.
